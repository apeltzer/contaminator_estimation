## 1. nf-core/modules: `somalier/contamination` (new module)

**Title:** `New module: somalier/contamination`

Wraps `somalier contamination` (somalier >= 0.3.2): CHARR contamination per sample and exact anchored (conpair-like) contamination MLEs for every ordered pair of the given `.somalier` files.

- input: `tuple val(meta), path(extract, arity: '1..*')`, `tuple val(meta2), path(sites)` (sites VCF with INFO/AF, the one used for extract)
- output: `samples_tsv`, `pairs_tsv`, versions topic
- same container as `somalier/extract|relate` (somalier 0.3.6)
- tests: nf-test with snapshot + stub. Test data: 3 `.somalier` files extracted from `genomics/homo_sapiens/illumina/bam/*` against `delete_me/somalier/sites_chr21.hg38.vcf.gz` (requires INFO/AF in the sites file; otherwise add a small AF-annotated sites file to test-datasets).
- `meta.yml` `containers:` section to be generated by the nf-core bot (`nf-core modules containers create`).

## 2. nf-core/modules: `somalier/relate` sites input

**Title:** `somalier/relate: add optional sites input`

Since somalier 0.3.2, `somalier relate` needs `-s/--sites` (sites VCF with INFO/AF) for correct hom-ref/hom-alt counts and `contamination_charr` in `samples.tsv`; without it CHARR is NaN and a warning is printed. Adds `tuple val(meta2), path(sites)` as third input (pass `[[:], []]` to keep the old behaviour). Breaking for callers (one more input), so the PR updates all tests and should be announced in `#modules`.

Diff: `modules/nf-core/somalier/relate/somalier-relate.diff`.

## 3. nf-core/modules: `somalier/extract` output naming

**Title:** `somalier/extract: name output after task.ext.prefix`

`somalier extract` names its output after the BAM's `SM` tag, while the module's stub uses `${prefix}.somalier`. Vendor pipelines often write identical `SM` tags (e.g. `SAMPLE`), which leads to input file name collisions in any downstream process that stages several `.somalier` files (`somalier relate`). The script now renames the single output to `${prefix}.somalier` (default `meta.id`), matching the stub. The sample name stored inside the file is unchanged (use `--sample-prefix` via `ext.args` to make it unique).

Only a single output is renamed: for multi-sample VCFs `somalier extract` writes one file per sample, which are kept as they are.

Diff: `modules/nf-core/somalier/extract/somalier-extract.diff`.

## 4. brentp/somalier: `extract --sample-name`

**Title:** `extract: add --sample-name to override the stored sample name`

`--sample-prefix` only prepends to the read-group `SM`. Pipelines that key everything on their own sample IDs need the stored name to equal that ID (and the output file to be `<name>.somalier`). Proposal: `--sample-name NAME` (single input only) sets the stored name and output file name. Would let the pipeline drop the `<id>__<SM>` naming and the header parsing for `relate -g`.

## 5. brentp/somalier: `contamination --pairs`

**Title:** `contamination: restrict anchored MLEs to a list of pairs`

`somalier contamination` computes all N×(N-1) ordered pairs, which is quadratic for thousands of samples although only a few pairs are needed (e.g. tumour/normal or longitudinal samples of the same individual). `-p/--tumor-normal-pair` handles exactly one pair per call. Proposal: `--pairs FILE` with `sample<TAB>anchor` lines; only these pairs are evaluated and written to `PREFIX.pairs.tsv`; CHARR is still written for all samples. Would replace the one-task-per-genotype-group workaround with a single task per batch.

## 6./7. Source attribution upstream

The `somaliercontam/*` modules depend on `bin/somalier_contam.py`, which nf-core/modules cannot use. Two options:

- **Short term:** publish `somalier_contam.py` as a small package (PyPI + bioconda, e.g. `somalier-contam`) and switch the modules' containers to the biocontainer; the modules can then be contributed as `somaliercontam/{restrictsites,identity,attribute,report}`.
- **Long term (preferred):** implement the mixture-model attribution and hom-hom identity as `somalier attribute` in Nim (it reads the same allele counts as `relate`/`contamination`). `tests/baseline/` (original script + `compare_to_baseline.py`) and the synthetic data with known truth provide the acceptance tests.
